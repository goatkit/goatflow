# 0.8.4 — External Identity Provider Integration (OIDC Client)

**Goal**: Let admins configure external identity providers (OIDC, Google) so org users can authenticate via them. Built on top of the existing `AuthProvider` registry pattern.

**Scope**: OIDC (generic), Google. Admin UI. Login page updates. Dead code cleanup.

**Guardrails**: YAML routing, SQL abstraction, 15-language i18n, DRY code, security-first (PKCE, state validation, JWKS verification, rate limiting, encrypted secrets).

## 3. Provider Dependencies + State Store

- [x] Define `OIDCProvider` interface (Option B — type assertion, NOT extending `AuthProvider`):
  ```go
  type OIDCProvider interface {
      StartAuthFlow(ctx context.Context, state string) (authURL string, err error)
      CompleteAuthFlow(ctx context.Context, code, state string) (*platformmodels.User, error)
  }
  ```
  The login handler dispatches via type assertion:
  ```go
  if oidc, ok := provider.(OIDCProvider); ok {
      user, err = oidc.CompleteAuthFlow(ctx, code, state)
  } else {
      user, err = provider.Authenticate(ctx, username, password)
  }
  ```

- [x] `internal/api/auth_oidc_handlers.go` — OIDC authentication handlers:
  - `handleOIDCRedirect(providerSlug string)` — GET `/auth/{provider}`:
    1. Look up provider config by slug and org
    2. Generate state token, store in StateStore (provider_slug + org_id)
    3. Type-assert provider to `OIDCProvider`, call `StartAuthFlow(state)` → get authorize URL
    4. Redirect to IdP

  - `handleOIDCCallback(providerSlug string)` — GET `/auth/{provider}/callback`:
    1. Validate `state` parameter (consume from StateStore, verify provider + org match)
    2. Type-assert provider to `OIDCProvider`, call `CompleteAuthFlow(code, state)` → user
    3. ID token validation happens inside `CompleteAuthFlow` (JWKS fetch, RS256 verify, iss/aud/exp/iat)
    4. If user has TOTP enabled, redirect to TOTP verification page
    5. Otherwise, redirect to dashboard

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| OIDC library | `golang.org/x/oauth2` + `github.com/coreos/go-oidc/v3/oidc` | Google's recommended, widely used, well-maintained |
| Provider interface | Type assertion to `OIDCProvider` (Option B) | Separates redirect-based auth from password-based; `AuthProvider` stays minimal |
| State store | In-memory `MemoryStateStore` with TTL | Simple, fast, single-instance deployment; future: Redis-backed |
| Client secret storage | Via existing `SecureConfig` system (AES-256-GCM) | Reuses existing encryption infrastructure |
| Provider registration | Via `init()` + `RegisterProvider()` | Follows existing LDAP/database provider pattern |
| User claims from IdP | Configurable per provider (email, name, groups) | Not all IdPs use the same claim names |
| TOTP flow | OIDC completes → TOTP challenge if enabled | Same 2FA experience regardless of auth method |
| Auto-provision | Configurable per provider | Some orgs want manual user creation, others want auto |
| Admin UI scope | In 0.8.4 | Required for first release |
| GitHub provider | Deferred to 0.9.0 | OAuth2 (not OIDC) provider — different flow |
| Routing | YAML (`routes/*.yaml`) | Project convention |
| SQL | `ConvertPlaceholders()` + `database.Rebind()` | Project convention for cross-database compatibility |
| i18n | 15 languages for all UI strings | Project convention |
| DRY | Shared OIDC helper functions, reuse existing cookie/token/session patterns | Project convention |
| Security | PKCE mandatory, state TTL 5min, JWKS signature validation, rate limiting on callback | Security-first principle |
